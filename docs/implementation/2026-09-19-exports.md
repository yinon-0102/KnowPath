# Durable learning exports — 2026-09-19

## Delivered behavior

`ExportService(repository, spaces, assessments, plans, runs, clock=None)` builds an immutable JSON snapshot synchronously and returns `{run_id, export_id, status: "ready"}`. Its Run is already `succeeded` and references the export ID. The service delegates command execution to `SpaceService._execute` using the shared learning repository, so the export row, Run/events and command replay response commit or roll back together. Repeating the same key and normalized JSON request returns the original result, including under concurrent memory/SQLite callers.

The SQL adapter persists `learning_exports` rows through the existing unit of work. The memory adapter stores them in the material repository's transaction snapshot, surviving reconstruction of `LearningState` with the same repository. This memory mode is deliberately not process-persistent; SQL rows survive process restarts.

`payload(export_id)` returns a detached snapshot for internal compatibility. `archive(export_id)` creates ZIP bytes in memory with one fixed entry, `learning-space.json`. Export IDs are database keys; neither IDs nor material filenames become filesystem paths. Reads fail with `DomainNotFound("export", id)` for unknown IDs and `DomainConflict("EXPORT_EXPIRED", ...)` at exactly `created_at + 24 hours`. No snapshot regeneration or TTL extension occurs on reads or idempotent replay.

## Snapshot contract

The payload has `schema_version`, `created_at`, `space`, `evidence`, `plans`, `sessions`, `versions`, and `source_refs`.

- Space fields are explicitly selected; goal, dates, weekly budget, profile values with provenance, scope IDs, fixed bindings and version counters are included. `space.state` preserves the previous internal export structure.
- Mastery and evidence fields use explicit public DTO field lists. Provider configuration, arbitrary persisted context and internal prompts are excluded.
- Plans contain safe metadata, request settings and task DTOs. Planner snapshots and raw task context are excluded.
- Sessions contain safe session/task context and public event acknowledgements. Raw event payloads and fingerprints are excluded.
- Material source references must resolve to an actual version and chunk belonging to a currently bound material. Chunk positions are reconstructed from trusted repository records. Referenced historical versions of those materials remain eligible; unrelated material references are omitted.
- The manifest records space/scope/profile/state versions, material version IDs and hashes, plan revisions and mastery policy versions. Graph versions remain attached to the explicit space bindings.
- Assessment questions, answer keys, attempt answers, provider keys and system prompts are never copied. The first export schema deliberately omits assessment question bodies altogether.

## Integration for the owning task

After constructing `self.plan_sessions` in `LearningState.__init__`, construct:

```python
self.export_service = ExportService(
    learning_repository, self.space_service, self.assessment_service,
    self.plan_sessions, self.run_service,
)
```

Delegate the existing methods as follows:

```python
def create_export(self, space_id, payload=None, idempotency_key=None):
    return self.export_service.create(space_id, payload, idempotency_key)

def export_payload(self, export_id):
    return self.export_service.payload(export_id)

def export_archive(self, export_id):
    return self.export_service.archive(export_id)
```

The POST route should pass the request body and idempotency key through to `create_export`. The download route should return bytes from `export_archive`, with `application/zip` and a fixed safe attachment name. Map `EXPORT_EXPIRED` to HTTP 410. Existing provisional `state.exports` storage can be removed after integration.

`learning_exports.space_id` references the owning space. Space deletion must handle existing export rows explicitly (a domain conflict or a deliberate cleanup policy) rather than allowing a SQL foreign-key failure to become HTTP 500. No API/state facade files were modified by this module task.
