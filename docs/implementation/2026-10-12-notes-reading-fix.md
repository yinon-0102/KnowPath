# 学习笔记阅读修复（2026-10-12）

## 原因

本地 Python 示例笔记册的首章已经保存自动总结正文、纠偏和历史版本。正文接口与历史接口正常；索引只返回摘要，不包含正文。

前端 Markdown 渲染器只允许 HTTP(S) 与页内地址，含中文、空格的虚拟 `.md` 文件链接显示为原始 Markdown。章节列表的标题虽然可点击，但没有明确阅读操作；打开后正文位于完整索引之后。滚动时学习路线悬浮条还会覆盖章节标题。

## 修复

- 只把当前笔记册登记的文件名映射为对应章节路由，保留未知相对链接及危险链接限制。
- 为已生成章节提供“查看笔记”，其他章节提供“查看状态”，区分生成状态与掌握状态。
- 章节正文先于索引显示，索引可展开；保留编辑、纠偏、来源、重试与历史操作。
- 初次进入章节时聚焦、定位正文；迟到请求不得改变新页面焦点，轮询不重复滚动。
- 笔记页停用学习路线悬浮条，避免标题遮挡；其他学习页保留原有悬浮行为。

## 验证

- 新增失败回归后修复：README 文件名链接、明确阅读入口、正文顺序、悬浮遮挡及迟到导航焦点。
- `npm.cmd run check` 通过；完整前端 `npm.cmd test`：310 passed。
- 笔记领域、API、生成集成与生命周期 pytest：60 passed，1 项既有 Starlette 弃用提醒。使用内存和临时 SQLite，未连接用户 MySQL。
- 在现有 5173/8000 服务上独立无界面浏览器验证真实章节，桌面 1440px 与窄屏 390px 均通过：列表点击、README 点击、自动定位、标题可见、刷新恢复、历史只读、取消编辑、无横向溢出、无运行时异常。
- 浏览器网络检查仅有 GET 和 CORS OPTIONS；没有提交正文或学习记录修改，阅读沿用现有辅助审计。
- 本地验收脚本及截图/结果位于 `.runtime.local/notes-reader-browser-verify.mjs` 和 `.runtime.local/notes-reader-20261012/`。

本次没有修改后端代码、迁移数据库或重启项目服务。当前前端服务动态读取页面文件，刷新即可生效。已有已生成笔记不需要重新生成；节点完成不等同于主题已掌握，也不等同于章节 `COMPLETED`。
