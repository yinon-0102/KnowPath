## 交付范围

- 自适应诊断：显式 opt-in、冻结题池、已有证据优先级、独立错题的前置排查、当前题单次答题、可重启恢复的决策轨迹。默认旧测验协议不变。
- 掌握度演化与动态复习：review-v2 统一状态/计划/演化的到期时间，使用不可变答题时间；演化区分原始观察、评分可用时间和后续纠错。保留知识版本与重置隔离。
- 预算比较：同一冻结快照的多个每日时间场景，依赖闭包、周预算、截止日期和可行子集；只预览、不替换真实计划。
- 历史回放：同一历史候选集的三种首主题排序、共有状态预测误差和真实连续延迟答题观测。清楚标明主题级代理、未知数据和非因果解释。
- API：四条新路由，创建测验增加 adaptive 字段；单独增量 OpenAPI fixture 保留历史契约。无新增 SQL 表或迁移。
- 前端：学习实验入口复用既有认证、幂等键、样式和空间选择；展示真实数据及空状态。

## 审查中修正的边界

1. 将 observed_at 与 created_at/reviewed_at 分开，延迟评分和重评不能伪装成间隔学习。
2. 复核保留 eligibility_before_revocation；历史资格不明的旧撤销记录保守排除，防止“复活”原本无效的证据。
3. review-v2 采用精确到期时间，消除状态/计划按天或按时判断的不一致；跨天测验以前次最后一次答题计算间隔。
4. 旧数据答题时间补全以非锁定方式读取不可变 attempts，避免与先锁答题再锁空间的命令形成锁顺序反转。
5. 回放只接纳截止时已经完成的测验；不把待完成或未来评分的测验加入历史比较。
6. 复测配对随中间独立答题更新时间，已知提示与重复题练习打断配对；不会把 23 小时后的练习与第 24 小时的答题算成完整一天的延迟复测。
7. 除单项上限外，限制回放决策主题总量及组合计算量，防止在空间锁内生成过大的缓存报告。
8. 提前终结自适应测验后，仍禁止对未展示的题目进行评分/题目复核，避免泄露隐藏题池。
9. 并发诊断在发布及下一题选择时再次核对已展示题族，避免两个同时生成的快照重复确认同一缺口；保留首次有效观察，超出在线检查上限时明确停止出题。
10. 自适应冻结输入同样补全旧数据的实际答题时间；预算比较尊重显式未到期标记，不会在复习当天提前消耗预算。
11. 删除资料后的空状态保持未知且不安排虚构复习；纠正错误评分按原始答题时间切换合法锚点，复核本身不增加间隔。
12. 旧版缓存的 mastered 结论由状态、计划与演化共用的只读投影重新验证，依据真实答题时间及当前 MasteryPolicy；旧评分时钟造成的虚假间隔不能让计划跳过学习。保留失效、重置和 unstable 语义，不改写持久化证据与状态。

## 使用与限制

- 从前端“学习实验”选择真实学习空间，开始诊断、读取演化、比较时间预算或执行历史回放。
- 诊断生成沿用现有后台模型任务；题池没有新的已验证题族时会明确停止，不制造题目或虚构成绩。
- 排序、复习与预算是透明的版本化规则，未经真实学习实验校准；证据均值不等于掌握概率，预算覆盖不等于学习收益。
- 回放比较首主题优先级，不模拟未选择题目的反事实答案。延迟复测只是观察结果，不建立策略优越性的因果结论。
- 实际模型、MySQL 及外部索引/对象存储测试需要显式测试环境，本次不读取真实密钥、不启动迁移、不操作线上数据。
- 已按模块提交至当前开发分支，提交信息采用英文前缀与中文说明；未推送或部署，用户原有的无关改动保留在工作区。
