# 学习空间持久化实现

沿用已确认的 MySQL 业务存储与仓储分层设计，继续按模块落地 API.md 第 5 节。

## 本批范围

- 学习空间基础字段、固定资料版本绑定、学习范围、画像及独立版本号存入 learning_spaces。
- 使用显式空间仓储；SQL 行锁完成版本检查与修改，内存实现保留相同语义。
- 创建空间、修改范围的 Idempotency-Key 与资源修改同事务提交，并保存响应快照；PATCH 支持提供 key 重放，未提供时由 expected_version 防止覆盖。
- 新增 profile JSON 与幂等响应 JSON 的增量迁移，回填已有空间画像。
- HTTP 请求校验未知字段、名称、预算、日期、偏好和必要版本；学习范围只接受已绑定快照内的主题。
- 保留原始资料绑定，上传新版本不自动替换已绑定空间。重建服务后从绑定版本恢复当前占位主题索引。

## 边界

测验、计划、证据、会话及学习状态仍为现有内存实现，本批不把它们伪装为已持久化。空间的临时学习状态与活动会话单独保留在 LearningState 的运行时缓存，避免将无法恢复的活动会话写入数据库。Neo4j 的真实图谱及前置关系尚未接入，因此本批不生成虚构的前置主题。

## 验证与交付

1. 先添加重建应用、幂等重放、版本冲突和范围约束的失败测试。
2. 实现空间仓储、服务与 HTTP 装配，并保持已有学习流程通过。
3. 升级本地 MySQL，验证迁移一致性和多应用并发更新。
4. 代码审查、完整学习测试后按数据库、业务、文档提交并推送。


## 当前验证

- 本地 SQLite 学习空间、既有状态流程和迁移测试通过。
- 本地 MySQL 已升级到 `0003_space_profiles`，`alembic check` 无待生成迁移。
- MySQL 回归覆盖同幂等键并发重放、不同键版本竞争、资料新版本提交时的旧快照、空间创建与资料删除互斥。
- 测验、计划、证据、会话和学习状态仍是运行时内存数据，后续模块需要独立持久化。
