# 计划与学习会话实现

沿用已经批准的 API 与架构设计。业务真相在 MySQL，内存实现只作为可替换测试仓储。

## 实施顺序

1. 扩展现有计划、任务、会话表，保存输入快照、任务排序/变更历史和会话终态响应；共享现有 Unit of Work 与幂等表。
2. 用可配置规则进行拓扑约束、到期复习/薄弱/未学优先级、分钟装箱与目标日期检查。约束不可满足时返回具体冲突与可调整项。局部重排保留历史和未受影响任务，原计划保留并标记 superseded。
3. 实现严格请求校验、乐观版本冲突携带最新计划、创建/启动/事件请求重放；同一空间以父行锁序列化会话，数据库唯一活动空间约束兜底。
4. 会话事件与 assisted 标记在同一事务提交，事件重放先于终态检查；finish 保存稳定响应，连接时长与自报时长分开。
5. memory/SQLite/MySQL 回归、迁移检查和独立代码审查后按模块提交。

## 规则说明

- session_count 为最多 3–5 个会话容量槽，minutes_per_session 为每槽上限；任务不为填满时长而复制。计划按 UTC 日期、每天最多一槽排期，默认考虑滚动七天的 weekly_minutes 上限。
- 估时与复习间隔由版本化策略提供；复习候选按有效独立证据的提交次数采用 1/3/7 天间隔，并保存原因。不是实际学习时间或认知能力推断。
- local_replan 复制历史任务时记录 origin_task_id，原任务与会话关联保持不变。受状态、来源、前置或范围变化影响的未完成任务重新安排；其他任务保留设置和顺序。
- 当前资料层仅生成来源章节主题，尚未接入持久化知识图谱关系；规划器只使用有来源或确认的前置关系，不能宣称已提供完整知识图谱调度。

## 并发与调度复核补充

- SQL 加锁读取刷新已加载任务和会话；空间锁内读取最新学习状态、证据，防止 REPEATABLE READ 的早期快照污染计划。
- 历史、范围外、已完成和已跳过任务不能启动会话。
- 未掌握且延期的前置阻断直接和间接后继，返回 `PLAN_CONSTRAINT_UNSATISFIABLE`，保留原计划。
- 到期 mastered 主题在满足拓扑依赖后获得复习优先级；不可拆分任务的策略估时不得缩短以满足槽容量。
- 回归覆盖 memory/SQLite 以及真实 MySQL 两连接的事件与结束、重复结束、启动与完成、评分与计划创建竞态。
