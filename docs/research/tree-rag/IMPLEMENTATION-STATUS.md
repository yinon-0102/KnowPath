## 真实开发过程

公开样本来自项目记录的教材、Project Gutenberg《论语》与政府法律PDF。源文件SHA256已核验。
建库使用独立SQLite和唯一Qdrant collection，没有修改现有业务库或默认线上检索配置。

dev-v1运行2个请求后因修正请求超输入预算中断，保留原始失败、完整计划分母和代码快照。
一次单独诊断测得输入7977→9349→13888字节，第三次超过12000上限。
修复保留全部原文与必要要点，压缩重复的成功核验反馈，并让核验只接收当前草稿。

dev-v2运行3个请求后保留中断记录：核验扩展了用户未要求的全局任务，且模型未稳定给推导内容加可见标记。
修复必要要点的范围规则，并根据已核验的kind添加固定类型标签，不改写已核验正文。
没有提高12000输入/2000输出上限，也没有删除、修饰或隐藏此前运行结果。

dev-v3已按固定配置完整执行40题A/B1配对：80次请求，A/B1各15次正常返回、各25次失败。
失败包括37次输入预算超限、12次模型响应无效、1次核验异常。旧失败记录未保留足够阶段信息，
不能把全部无效响应推定为输出截断。默认配置尚未通过验收。
见[完整开发报告](evaluation/runs/2026-09-20-dev-v3/summary.md)与
[逐题原文及回答](evaluation/runs/2026-09-20-dev-v3/review.md)。
模型返回answered/supported只说明运行时模型判断，人工任务成功率、胜负与采用结论均保持未知。

法规14题的[代理辅助分析](evaluation/runs/2026-09-20-dev-v3/law-review-notes.md)发现：
部分回答在证据已进入上下文时仍遗漏条件，B1扩展也不一定形成相对A的新证据。这些是待人工核对的
具体疑点，不是人工评分；不能用100%的区间覆盖替代语义验收。

完整运行归档后补齐了真实插件prepare/delete入口、固定调用费与缺失输出价格估算、
更短单次超时的保留、生成/核验共享且可冻结的模型I/O预算，以及白名单失败阶段/计数诊断。

[诊断记录](evaluation/runs/2026-09-20-budget-probe-v4/README.md)。该定向小样本不能证明整体质量提升。
