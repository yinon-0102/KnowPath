# 真实开发运行记录

公开资料为线性代数教材 Markdown、Project Gutenberg《论语》简体 TXT、政府公开法律 PDF。
原始来源与文件哈希见 `../real-draft/source-manifest.json`。真实建库使用独立 SQLite 与唯一
Qdrant collection，共934个检索块；没有修改业务数据库或默认线上插件。

## 实验顺序

| 目录 | 用途 | 状态 |
|---|---|---|
| `2026-09-20-dev-v1` | 首次真实开发尝试 | 执行2次后中断，保留全部失败和80次计划分母；单独诊断发现修正输入超限 |
| `2026-09-20-dev-v2` | 压缩重复修正反馈后的开发尝试 | 执行3次后中断，保留原始结果；发现核验扩大必答任务及推导标记问题 |
| `2026-09-20-dev-v3` | 固定提示词与预算的完整开发运行 | 40题×A/B1，原始结果与最终统计见该目录 |
| `2026-09-20-budget-probe-v4` | 预先指定5道已见失败题，统一24k/4k预算诊断 | 10/10执行，4次正常返回、6次失败；不作为整体质量提升证据 |

这些是先后改变配置的开发实验，不是同一冻结实验内的自动重试。不能合并、筛选其中的有利结果
作为最终80次统计，也不能把前两次中断的未执行请求当作成功。v3 不因单题失败中断重跑。

每个目录保存冻结配置、原始 JSONL、报告和当时的代码快照。输入归档保留运行时实际身份、
来源全文、split和rubric。归档不包含模型凭据、环境文件或数据库连接密码。
冻结清单保存的是运行机器的原始绝对路径；后续代码变更应触发原校验器拒绝重算，而不能改旧hash
冒充新代码参加了旧实验。复现实验应在隔离环境使用相应代码/输入快照，明确记录路径重映射与新冻结ID。

无需还原或执行旧代码即可校验归档完整性，从仓库根目录运行：

```powershell
python docs/research/tree-rag/evaluation/verify_archive.py docs/research/tree-rag/evaluation/runs/2026-09-20-dev-v3
```

工具逐一比对原冻结hash与归档字节；这是本地完整性检查，不是签名认证或人工质量评审。

## 结果解释

正常返回 answered/partial/insufficient/clarify 是服务完成状态，不是人工判分。
失败请求保留在完整分母；失败时未观测的证据和费用保持未知。
候选、重排、上下文和引用覆盖是原文区间覆盖，不保证答案语义正确。

全部60题仍为待人工审核草稿。开发集运行不解锁保留集：需要真实人工审核、冻结供应商价格，
并预先填写四个部署延迟/费用门槛。没有这些条件时不宣称B1胜出，也不自动上线A。
人工复核入口是v3目录的 `review.md` 与 `human-review-template.json`。

最初建库早于完整调用审计实现，部分失败用量和实际账单无法回补；复用耗时不能代替首次构建耗时。
新构建已有持久调用预约与安全用量记录。本次未知成本不计为零。
