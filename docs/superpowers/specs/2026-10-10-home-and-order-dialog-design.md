# 首页与学习顺序弹窗设计

状态：第三版设计与静态预览已完成，尚未修改产品代码。

## 方向

保留截图二的主视觉、文案、知识轨道插图与蓝灰配色。第三版改为“当前学习桌面”：主视觉 → 当前路线 → 当前空间资料与最近笔记。顶部已有学习空间模块，因此首页不再重复列出空间目录。

相比上一版“继续学习主卡 + 四个快捷入口”，第二版不再增加快捷入口网格，首页以具体学习内容为主。相比统计仪表盘，第二版不依赖缺失的全局累计或趋势接口。复用现有真实功能，不向系统写入示例内容，不自动重启服务。

## 首页

1. 保留主视觉，优化与下方区域的衔接。
2. 主视觉下方缩小统计为文字摘要：真实空间数、资料数和当前计划节点数；不再单独占用一整排大统计卡。
3. 主区域为一整块“打开你的学习路线”。左侧约 56% 展示所选空间、真实下一步、节点和唯一主操作；右侧约 44% 展示当前轮的连续节点目录，标题与原文章节分别标明。超过五项时只显示当前节点周围最多五项，并提供完整路线入口。
4. 复用工作台的真实下一步：活动会话、选择范围、创建计划、重规划、复习或下一任务。任务顺序取 context.position，多空间可切换。原文阅读与个性化讲解入口跟随节点，不虚构已经生成的讲义；讲义生成沿用用户明确触发的既有流程。
5. 当前轮完成数量只统计非历史任务，跳过单独标注。缺少计划、未加载和失败不能当作零进度。正在学习或暂停状态来自真实会话，不以空间 active 状态推断。
6. 路线卡左侧顶部使用当前空间选择器，显示空间名称、目标摘要与真实计划状态。切换空间时路线、资料和笔记必须一起切换；空间未选定或加载失败时清空旧内容，不沿用上一个空间的数据。空间管理入口由顶部导航和路线卡的空间名称承担。
7. 路线卡下方为“当前空间资料”与“最近笔记”两栏。资料按当前空间绑定关系筛选，按真实导入时间降序显示最多四份，缺失日期置后；名称、文件类型、解析状态与原文件阅读入口直接可见。笔记只读取当前空间的笔记册索引：有章节时显示最近更新章节及状态，没有正文时显示“尚未生成学习笔记”和真实触发条件，不显示伪造摘要。
8. 窄屏顺序为主视觉、当前下一步、路线目录、当前空间资料、最近笔记；不横向挤压。移除重复励志面板、“今天任务”不准确表述、空间目录和重复顶栏的快捷入口网格。无资料或无笔记时使用实际选择资料、查看笔记册入口。

## 排序弹窗

- 桌面最大宽约 1000px，标题、正文、底部操作分区。正文左右两栏：左约 240px，右侧为路线编辑；按视口高度限制内部滚动，标题与底部操作可见。
- 左侧将单一下拉框改为三项单选卡，分别解释原文顺序、智能安排、自定义顺序；下方是资料优先级与次要“重新读取计划”操作。右侧是连续编号的完整路线清单，保留已完成、跳过、历史和活动会话节点的实际槽位；固定原因就地展示。
- 节点行约 88px 起，内边距约 16px，行间距约 12px。顺序编号、知识点标题、原文章节、预计时间对齐。上下移触控范围至少 44px，间隔 8px，长标题自然换行。
- “预览顺序”后在同一清单显示候选位置与变化提示，不再追加一套重复长列表。排期变化以简短摘要显示，明细可展开；冲突就地说明。固定槽位与最终资格以后端预览为准，预览前的标识不得声称校验已通过。
- 底部左侧“取消”与未应用状态，右侧“预览顺序 / 应用顺序”。未通过预览时应用禁用，保留错误、冲突草稿、键盘焦点、关闭和幂等行为。窄屏上下排列，移动按钮仍保留可访问名称，不仅依赖拖拽。

## 实施与验收

主要修改 app.js、styles.css、plan-order.js，数据整理必要时放入 workbench.js。复用现有工作台、进度、空间、资料和笔记索引接口，不增加常驻服务或数据库迁移。

验证 1440px、1024px、390px，覆盖空数据、单/多空间、长标题、多节点、加载失败、活动/暂停会话、排序预览与冲突；检查键盘焦点、触控范围、无横向溢出。运行前端 check 和完整测试，不自动重启项目服务。

## 第二版预览与边界

预览使用 2026-10-10 只读取得的本地记录：一个已有 Python 学习空间、两份资料（其中一份绑定到当前空间）、五个未完成节点，当前计划状态为 needs_replan，无活动学习会话。预览如实显示“待重新规划”；章节顺序取当前计划，不在设计过程中重排任务。空间名称中的“示例”是已有记录名称，不是新写入的演示数据。

静态预览中的按钮用于展示位置与层级，尚未接入操作。桌面和窄屏预览均已渲染，页面没有横向溢出。项目产品代码、学习记录及运行服务未修改；正式实施仍须验证内部滚动、焦点与实际交互。
