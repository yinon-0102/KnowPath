# 自动连接本地后端设计

## 背景

当前运行的 KnowPath 前端（`frontend/`）默认进入示例模式，用户需要打开连接弹窗并手动复制本地会话令牌。代码中还保留了内置示例空间、示例资料、示例测评和演示分支，容易让用户误以为这些是真实后端数据。令牌实际由后端写入 `py/.learning-token.local`，因此本地启动时不应要求用户再次复制。仓库根目录还保留旧首页和旧 Python 静态服务启动路径。

## 目标

- `frontend/` 页面启动后自动读取本机后端令牌并连接真实 API。
- 删除当前页面中的令牌输入框、连接表单、手动连接按钮和相关提示。
- 删除前端示例数据、示例测评、示例计划、示例学习记录、示例模式状态和相关演示文案；所有页面只使用后端真实数据。
- 删除根目录遗留首页和旧 Python 静态服务，启动器统一启动 `frontend/server.mjs`。
- 令牌只在本机回环服务与当前页面会话之间传递，不进入源码、静态资源或服务日志。
- 自动连接失败时显示可重试的服务错误，不退回到要求用户复制令牌的流程。

## 方案

前端静态服务在回环地址提供一个专用启动配置接口，例如 `GET /__knowpath/local-auth`。接口由服务端读取与后端相同的 dotenv 配置，并从 `LEARNING_LOCAL_TOKEN` 或配置的令牌文件读取令牌。响应仅包含当前令牌和固定 API 地址；接口只接受本机 Host，使用 `Cache-Control: no-store`，不记录请求路径、请求头或响应内容。

应用初始化时先读取已有 `sessionStorage` 令牌；没有令牌时请求该接口，写入当前标签页的 `sessionStorage` 后直接加载真实资料。应用不再有 demo/live 双模式，后端连接失败只显示真实服务错误和重试操作。旧的 `#local_token` 片段和手动输入机制一并移除。

Node 前端服务器实现该接口，且只在自己的回环静态服务上提供；API 服务本身不新增令牌读取路由。这样不会改变后端鉴权合同，也不会把令牌暴露给局域网或外部来源。

## 错误处理

- 令牌文件缺失、格式无效或启动配置接口失败：显示“本地服务配置不可用”和重试操作。
- API 未启动或 API 返回未认证：显示后端连接错误和重试操作。
- 不显示令牌值、文件路径中的秘密内容或带令牌的 URL。
- 自动连接期间避免并发发起重复的配置请求。

## 测试

- Node 服务测试：配置接口成功返回；非回环 Host、缓存和静态路径限制仍生效；令牌文件和 `.env` 不可直接访问。
- 前端测试：无 session 令牌时自动获取配置并发送 `X-Local-Token`；失败时只显示重试状态；不再渲染连接表单。
- 全部现有前端测试和服务测试通过。

## 迁移与清理

- `store.js` 只保留真实页面共用的转义、存储、文件校验、PDF 缓存和来源定位工具；删除 `makeDemo`、`loadDemo`、`spaceProgress` 和示例数据常量。
- `workbench.js` 删除 demo 计划、demo 进度和 demo 学习记录生成器。
- `learning.js` 删除本地出题和本地作答路径，测评只调用后端接口。
- `app.js` 删除 demo 状态、示例数据读写、示例重置、示例上传/计划/空间分支和示例文案。
- `frontend/README.md` 改为只描述真实后端流程，不再把示例体验作为启动或验收方式。

## 不在范围内

- 不改变后端令牌生成、校验、轮换或 API 路由。
- 暂不重构当前首页的视觉布局，沿用原有配色和风格。
- 不把令牌写入 Git、前端构建产物或浏览器持久化存储。
- 保留真实业务页面和后端接口；测试中使用隔离响应，不保留运行时示例数据兼容层。
