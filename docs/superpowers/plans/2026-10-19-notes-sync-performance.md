# 笔记同步性能优化

## 范围与实现

- 将章节循环中的会话查询、生成记录查询合并为同步内的一次读取。
- 每次同步按空间缓存主题版本与证据 epoch，同一证据只校验一次；缓存不跨请求。
- 共享生成任务的运行状态读取结果，仍仅保存发生变化的章节。
- 保留事务边界、章节先于生成记录的加锁顺序及原有完成与证据判定规则；无并发线程、无数据库迁移。

## 一次性能对比

按用户要求不重跑全量测试。原库仅允许 SELECT 导出，本地 SQLite 副本中的同一份真实数据分别运行修改前后同步；运行结束回滚。数据库副本与原始学习内容仅保留在本机 `.runtime.local/notes-sync-perf-20261019/`，不提交。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 笔记章节 | 49 | 49 |
| 同步耗时 | 7.559 秒 | 0.106 秒 |
| SQL 查询 | 2178 | 70 |
| 发生变化的章节 | 0 | 0 |

本次同步耗时缩短约 98.6%，查询减少约 96.8%；49 章结果一致。样本是数据已完成后的同步读取路径，没有触发章节写入，不覆盖全部状态变化分支。

这些数字属于本地 SQLite 数据副本，不能外推为线上 MySQL 或原先 131～185 秒完成请求的整体耗时。其证明的是消除了重复查询和重复数据解码；真实请求也包含计划投影、事务等待与导航等其他耗时。
