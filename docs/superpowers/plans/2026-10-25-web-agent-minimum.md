用户已批准先交付最小可靠版本。此文档调整交付顺序，不宣称原 Task 0–13 已完成。

目标：普通聊天、阅读追问、讲义追问、测评求助统一调用真实 MyFunctionCallAgent；新消息拥有跨重启恢复的 L0–L5。保留既有消息/API/SSE 和业务权威。

首版允许同步维护和同空间串行执行。记忆管理 UI、手动固定卡、全量历史回填、高级冲突消解与异步索引优化后置。原始历史继续可查看，不把缺失来源的旧数据猜成当前记忆。

## 实施顺序与退出证据

- [x] 关闭请求工作副本、递归来源资格和最终发布完整依赖校验；失败/取消不留下记忆，成功回答与记忆/事件/审计同事务。
- [x] 工厂构造真实通用 Agent，借用请求 MemoryManager，external commit，严格取消与预算，使用 Web 模型配置及限定工具；不创建 shell 工作区。
- [x] 从原 RAG 抽取 prepare_evidence，保留单一检索/范围/重排算法；检索不生成回答，引用由请求内证据注册表恢复。
- [x] 实现统一运行时和 scoped recall/remember/search 工具；资料回答通过来源及声明校验，历史问题实际调用召回，记忆与资料只作为不可信内容。
- [x] API/Worker/普通/阅读/讲义/测评求助全部接线，生产默认停止使用旧回答执行链；保留业务服务与发布审计。显式注入的自定义旧生成器保留兼容接缝，旧私有实现删除仍属于原计划后续清理。
- [x] 验证重启恢复、范围切换与旧 epoch recall、来源删除、取消、重复执行、提交不确定性和 SSE；运行离线 Agent/兼容回归以及独立 MySQL 并发测试。

独立 R0 制品与旧数据迁移仍是后续目标环境切换条件；本阶段不部署、不调用在线模型、不访问日常数据库。完成最小版本须有所有入口的实际执行证据，不能用工厂单测或记忆组件绿灯代替。

## 当前实现与证据（2026-10-25）

生产默认模型配置直接进入 WebAgentRuntime → MyFunctionCallAgent。工具仅 recall / remember / search；Agent 与声明核验共用同一请求模型预算。资料正文由核验声明重建，不提前向 SSE 发布候选。新消息冻结 runtime_version；已开始外部执行但无成功收据的任务不自动重放。

L0 卡片、L1/L2/L3 checkpoint 与 L4/L5 原始投影/索引由请求副本加载，提交共享业务事务。默认同步维护，不启用额外模型反思调用。完整依赖包含外置集合、source_item_ids 和来源收据；发布先锁资料与消息，再检查 memory 当前读，撤销窗口使整次发布回滚。

原文 block ID 与检索 chunk ID 分别保持原有身份，通过真实 SourceSpan 覆盖衔接授权。新版资料检索已有真实 SQL / 本地 Qdrant / 离线 SDK 模型的完整 Web 回归，未以伪造检索标识代替真实仓库。

- 完整离线 Agent：agent-jl1dgw_5，478 passed / 50 skipped，退出码 0；跳过项主要是显式 MySQL 和后端不适用用例。
- 最终独立 MySQL：agent-x9dqryqa，65 passed / 9 后端不适用 skipped，退出码 0；包含真实入口、独立连接撤销、租约接管和 SQL 锁序。
- 独立规格复审：agent-srab6t8j，79 passed / 28 skipped，最小范围 PASS。
- 最终质量复审：agent-2ld7zvwp，34 passed / 3 MySQL-only skipped，两项质量问题修复后无剩余 P1/P2。
- 最终完整兼容回归：compatibility-9cgz_phr，1472 passed / 88 skipped / 1 既有弃用 warning，退出码 0，无收集错误。

质量复审后的修复：递归来源缓存仅存活于一次顶层资格求值，下一次检查重新读取撤销状态；物理模型请求使用绝对回合 deadline 和可取消的有界 HTTP owner，阻塞请求直到真实退出才归还全局容量。模型限流/不支持能力错误码保持原公开语义。
