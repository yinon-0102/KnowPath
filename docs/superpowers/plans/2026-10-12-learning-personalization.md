## 已接入的流程

1. 阅读会话与题目曝光分别记录服务端活动时间。每 30 秒心跳，90 秒未收到心跳停止累计；手动暂停、隐藏、断线、作答、等待各自独立。暂停原因不会被自动恢复清除。计时区间可以按计划时区重新分日，历史墙钟时间保留，缺少心跳的记录标注质量问题。
2. 学习结束、测评结算、评分复核、题目隔离和状态重置请求自动调整。事件与测评结算同事务保存；规则任务在现有模型 worker 中消费 Outbox。失败不撤销已完成评分，工作台可以查看调整、重试及预览撤回。
3. 自动调整保护已开始、完成、跳过、历史和明确延期的节点，保持任务与节点身份以及当前原文／自定义顺序。依据过期安排诊断，有效错误安排练习，到期安排复习，已掌握未到期保留路线但无需安排。范围或资料失效必须显式更新。
4. 时间预测使用学习／作答两个独立基线与最近最多 20 份可靠样本，五份先验、加权几何平均、速度倍率 0.5—2。必要前置的有效困难最多增加 40% 补学时间；无关上一节点的成绩不作为下一节点困难的依据。关闭个性化后使用固定基线。
5. 新计划默认滚动预算，已有固定会话模式保留。比较、采用、调整与撤回共用调度器；单节点可跨天分配学习与作答时段。已发生时间与剩余预约分别扣容量，完整路线保留，待排节点仍可阅读。截止日期容量不足显示缺口，不通过缩短预计时间制造可行性。
6. 打开个性化讲解时比较来源与适配指纹。后端提供当前主题与必要前置的有效证据摘要、计时质量和教学动作，模型组织表达；保留用户风格和全部未学习的核心知识。旧版本继续可读，成绩变化不冒充原文失效。
7. 策略分析生成一条主要建议，区分有效薄弱点、未知证据、到期复测和预算缺口。先预览再确认，调用既有诊断或统一预算命令，不将历史代理指标描述为因果提升。

## 持久化和接口

迁移 `0018_learning_personalization` 新增 `budget_comparisons`、`plan_adjustments`、`policy_recommendations`，提供内存实现。计时、预测与讲义适配保存在现有 JSON context。

| 方法与路径（均以 `/api/v1` 开头） | 用途 |
| --- | --- |
| PATCH `/plans/{plan_id}/schedule` | 采用已冻结比较方案；检查方案、计划版本与快照 hash |
| POST `/plans/{plan_id}/refresh` | 请求／恢复调整 Run |
| GET `/plans/{plan_id}/adjustments` | 调整历史、前后安排与错误 |
| POST `/plan-adjustments/{identifier}/revert` | 默认预览；`apply=true` 确认撤回仍可恢复部分 |
| POST `/learning-spaces/{space_id}/policy-recommendations` | 当前状态建议与历史解释 |
| POST `/policy-recommendations/{identifier}/apply` | 默认预览；`preview=false` 确认应用 |
| POST `/sessions/{session_id}/activity` | 学习心跳及暂停原因 |
| POST `/assessments/{assessment_id}/activity` | 当前题目曝光、心跳及暂停原因 |

所有接口继续使用本地鉴权、既有错误契约和幂等机制；写入请求遵循现有 `Idempotency-Key` 要求。版本或快照变化后重新预览。

## 前端入口

- 空间设置：自动调整、时间个性化、讲义适配三个开关，默认开启。
- 学习计划：滚动／固定模式、每日预算、窗口、时区，以及预算比较与采用。
- 学习路线：分项预计时间、跨次安排和待排原因。
- 测评完成页：调整 Run 的实际状态，查看调整或恢复等待。
- 调整记录：前后变化、失败原因、重试、撤回预览与确认。
- 高级分析：一条主要建议、依据及确认入口。
- 阅读界面：服务端活动时间与暂停状态；15 分钟无操作只提示核对，不认定用户没有阅读。

学习页更新沿用局部 DOM 保留路径，不通过普通计时更新重建 PDF 阅读窗口。

## 验证与实际边界

专项覆盖跨午夜、失联截止、手动暂停、测评／阅读互斥、计划身份、预算快照竞争、关闭开关后的迟到任务、撤回预览、笔记与调整同时入队、讲义取消及资料删除。迁移验证使用隔离 SQLite，不操作用户数据库。

预测评估函数为 `plans.duration.evaluate_duration_predictions`：按时间切分可靠样本，仅用严格早于留出样本的数据训练，输出分阶段 MAE、固定基线 MAE、样本数和覆盖率。当前服务尚未迁移和重启，本次只验证算法与测试样本，没有据此宣称真实用户预测改善。未配置独立 MySQL 测试库时 MySQL 专项跳过；真实数据库并发和桌面／窄屏浏览器使用仍需上线验收。

最终验证：后端完整 `pytest knowpath_backend/test` 为 **3218 passed、306 skipped**；前端 `npm.cmd run check` 通过，完整 `npm.cmd test` 为 **325 passed**。跳过项包括需要独立 MySQL 配置等外部条件的测试。首次完整回归中发现并修复了笔记快照入队顺序与测试检索配置隔离问题，未把失败记作通过。
