# 任务日志阅读方式

默认文本控制台展示动作、阶段结果、数量、耗时和可解释的失败原因。方括号内最多保留一个稳定的短追踪标记，便于区分同时执行的任务；完整请求、任务、模型调用编号和原始事件名仍保留在 JSONL 文件中。DEBUG 行保留详细关联信息。

以下是格式示例，数字仅作说明，并非本次真实 PDF 测试结果：

```text
读取并解析资料：开始；原文件字节数：120000
读取并解析资料：已完成；解析片段：37；耗时：670 毫秒
解析结果已保存，已进入图谱处理队列；解析片段：37
写入知识图谱并回读核验：已完成；知识节点版本数：37；来源片段数：37；语义关系数：0
生成检索向量：已完成；来源片段数：10；生成向量数：10
写入检索索引：已完成；来源片段数：10
本批向量和索引写入完成（尚未发布）；已处理片段：20/37；批次：2/4
核验全部检索索引：已完成；来源片段数：37
图谱和索引已准备好，等待审核发布；尚未对检索生效
知识图谱发布操作已完成；发布版本：1
```

问答日志记录检索候选数量、选中数量、校验后的正文字符数及引用数量。校验失败会区分结构错误、正文异常、缺少引用、引用越界和重复引用，不记录原始正文或引用内容。

“提交至本次执行”是任务年龄，重试时包含先前执行及等待时间，不能当作纯排队耗时。“后台任务已完成”只表示当前作业结束；资料准备完成仍须审核发布。向量或索引写入失败不会输出该阶段的完成事件。未知事件显示原事件名，不猜测业务结果。

部署后需重启加载这些代码的服务。
