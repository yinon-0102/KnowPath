# 请求级文档范围

实现日期：2026-09-29。此次仅涉及后端、测试和接口文档，未交付前端修改。

## 范围与接口

`POST /api/v1/learning-spaces/{space_id}/messages` 新增可选 `material_ids`。
不传或 `null` 保留空间内默认检索；显式列表支持 1—5 个资料 ID。请求携带现有的 `Idempotency-Key`，按部署配置携带 `X-Local-Token`。

```json
{
  "message": "说明本资料里的梯度下降",
  "stream": true,
  "material_ids": ["资料A的ID"]
}
```

后端将选择与空间授权来源取交集。多选允许联合检索，未绑定的资料导致整次请求被拒绝，空选择不能隐式扩大范围。选择锁定空间绑定的版本，而不是资料库的最新版本。

## 实现链路

1. `conversations/schemas.py` 校验、去重和规范化 ID。
2. `conversations/document_scope.py` 生成请求范围快照和稳定标识；不改变持久化 RAG scope。
3. `MessageService.send` 在消息事务内冻结选择、来源、范围版本，并将选择纳入幂等请求。
4. 旧检索只接收筛选后的来源。`RagPipeline.answer` 在保留空间级发布检查后缩小 manifest 及原文候选。
5. 现有关键词/向量过滤、树导航叶集合、语义单元、重排与引用身份校验继续约束筛选后的来源。
6. `_context_error` 再次核对冻结范围和实际来源，防止异步结果改变范围。

底层仍共享按嵌入配置区分的 Qdrant 集合，不需要数据库迁移或重建索引。

## 历史、恢复与删除

- 历史、摘要及长期召回按有效请求范围隔离；选择顺序不同不会产生不同范围。
- 默认全部资料与显式选择全部绑定资料具有相同有效范围；但显式选择不会复用缺少范围元数据的旧消息。
- A→B→A 的追问不会跳到较早的 A 对话；切回全部资料同样执行连续性检查。无法确定指代时澄清，不调用回答模型。纯澄清不将未交付的召回资料计为测评辅助来源。
- 消息快照随现有数据库记录持久化。后台任务重启仍使用原范围，既有取消、租约和过期上下文保护保持有效。新 RAG 已开始执行后的中断仍遵守原有禁止盲目重放模型调用的策略。
- 资料删除清理新增范围元数据并标记 `request_scope_invalidated`；历史记录不能因此被重新解释成默认全资料范围。未完成任务仍按现有删除策略取消。历史正文/事件遵循原有保留规则。

## 输出与日志

`message.completed.request_scope` 提供实际冻结范围。`request_scope_id` 标识有效来源范围；`mode` 保留用户采用默认或显式选择的方式。

结构化事件 `message.scope.frozen`、`message.scope.rejected`、`rag.scope.applied` 记录范围标识、资料 ID 或拒绝原因及来源数量；`rag.result` 增补范围标识与实际引用资料 ID。不新增文档原文或完整提示词日志。

## 限制

- 这是检索与上下文来源边界，不是新增的多用户权限系统，也不能阻止模型使用预训练知识；回答仍需证据核验。
- 第一版仍检查整个学习空间的索引发布完整性。若未选中文档索引损坏，单文档提问也可能被阻止；不会为绕过该校验而重建或伪造 scope。
- 前端仍按旧接口发送请求时，行为维持空间内全部允许资料检索。

## 验证

新增回归覆盖实际检索输入、重排输入、模型证据及引用集合，HTTP 校验、稳定幂等、队列恢复、历史和摘要隔离、切范围指代、资料删除清理。使用内存/SQLite、内存 Qdrant 与本地模型替身；不调用外部模型。未配置独立 MySQL 服务的测试保持跳过。

运行后端完整回归：在项目 `py` 目录执行 `python -m pytest knowpath_backend/test -q`。Windows 若需要指定 `--basetemp`，使用可写且位于 Git 仓库之外的目录，以免影响项目根目录探测测试。
